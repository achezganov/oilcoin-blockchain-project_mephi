# HTTP API OilCoin

Базовый URL локального Docker: `http://localhost:8080`. API используется для чтения учебной сети и состояния онлайн-арены; финансового публичного RPC, JSON-RPC Ethereum и внешнего API майнеров нет. Денежные и игровые действия выполняются HTML-формами через сессию и CSRF.

## Чтение

| Метод и путь | Ответ / назначение |
|---|---|
| `GET /health` | `status`, `database`, `height`; доступность приложения и загрузки состояния. |
| `GET /api/chain` | Параметры сети, `chain`, `pending_transactions`; полный снимок истории. |
| `GET /api/pending` | Массив pending-переводов. |
| `GET /api/balance/<address>` | `address`, `confirmed_balance`, `reserved_pending`, `available_balance`. |
| `GET /api/wallet/<address>/operations` | Адрес и `operations`: статус, блок, вложенная транзакция. |
| `GET /api/wallet/<address>/stats` | Баланс и агрегированная статистика адреса. |
| `GET /api/block/<index>` | `found`, `block`; если блок отсутствует — 404. |
| `GET /api/tx/<tx_id>` | `found`, `status`, `block_index`, `transaction`; если операции нет — 404. |
| `GET /api/address/<address>` | Балансы, операции и статистика адреса. |
| `GET /api/explorer/search?q=...` | Результат поиска по номеру/хешу блока, tx_id или адресу. |
| `GET /api/tokenomics` | `summary`, `charts`, `validation: {is_valid, message}`. |
| `GET /api/stats` | Только сводка токеномики. |
| `GET /api/demo/status` | Состояние demo; зависит от `ENABLE_DEMO`. |
| `GET /api/game` | XP, уровень игрока, буровая и миссии текущего аккаунта; требуется вход. |
| `GET /api/csrf` | `{csrf_token: "..."}` и session cookie; для отправки форм программным клиентом. |

История и публичные адреса видны всем посетителям. Пароли, хеши паролей и приватные ключи в публичном API не выдаются. Неверный формат адреса приводит к 400 в адресных endpoints. Неизвестный, но корректный адрес может иметь нулевой баланс — это не доказательство существования зарегистрированного владельца.

```bash
curl --fail http://localhost:8080/health
curl --fail http://localhost:8080/api/stats
curl --fail http://localhost:8080/api/block/0
curl --get --data-urlencode 'q=0' http://localhost:8080/api/explorer/search
```

Пример health на новой базе:

```json
{"status": "ok", "database": "sqlite", "height": 0}
```

`height` — номер последнего блока; количество блоков включает genesis и на 1 больше. Статус 200 означает успешную загрузку проверяемого состояния, а не независимый аудит или наличие распределённого консенсуса.

## Помощь и документация

Эти GET-маршруты доступны без входа и не изменяют игру:

| Путь | Ответ |
|---|---|
| `/docs/` | HTML-каталог публичных руководств. |
| `/docs/?q=комиссия` | HTML-результаты поиска по разделам; запрос до 120 символов, превышение — 400. |
| `/docs/<slug>` | Статья с боковым меню и оглавлением. Например, `blockchain`, `player-guide`, `faq`, `architecture`, `deployment`, `api`. |
| `/docs/<slug>/source` | Загрузка исходного Markdown-файла статьи. |

Неизвестные статьи и файлы возвращают 404. Значение `slug` выбирает запись из каталога, а не путь на диске. Статьи используют существующие Markdown-исходники проекта; SQLite для их чтения не нужна.

## Данные транзакции

Общие поля: `tx_id`, `sender`, `recipient`, `amount`, `fee`, `burn`, `timestamp`, `type`. Типы: `genesis`, `transfer`, `mining_reward`, `miner_fee`.

Подписанный `transfer` дополнительно содержит:

| Поле | Значение |
|---|---|
| `version` | Версия подписанного формата, сейчас 1. Это не версия блока. |
| `network_id` | Хеш genesis конкретной сети: подпись привязана к ней. |
| `sequence` | Последовательный номер исходящего перевода отправителя. |
| `public_key` | Ed25519 public key в hex. |
| `signature` | Ed25519 signature в hex. |

Денежные поля в JSON представлены числами, но проверки и подпись используют целые атомарные единицы: `1 OIL = 100 000 000 units`. Допускается не более 8 десятичных знаков. Для нечётного количества единиц комиссии burn округляется вниз до целой единицы; остаток получает майнер.

`tx_id` вычисляется из канонического подписываемого сообщения и подписи. Подмена поля ломает проверку. Монотонный sequence и идентификатор сети дополняют проверку повторов. Операция может присутствовать в pending без `block_index`; после майнинга она имеет статус `confirmed` и индекс содержащего блока.

## Изменение состояния

| Метод и путь | Поля формы | Авторизация |
|---|---|---|
| `POST /register` | `label`, `password`, `password_confirm`, `csrf_token` | Не нужна. |
| `POST /login` | `address`, `password`, `csrf_token` | Не нужна. |
| `POST /logout` | `csrf_token` | Завершает текущую сессию. |
| `POST /transaction` | `recipient`, `amount`, `fee`, `csrf_token` | Вход; отправитель из сессии. |
| `POST /mine`, `POST /mine/quick` | `csrf_token` | Только лабораторный `ALLOW_MANUAL_MINING=true`; обычно отключены. |
| `POST /game/upgrade` | `csrf_token` | Вход; покупка следующего уровня буровой. |
| `POST /demo/generate` | `csrf_token` | Вход и `ENABLE_DEMO=true`. |

Это **form endpoints**, а не JSON REST-методы: успешное действие обычно возвращает redirect в интерфейс, а результат/ошибку — flash-сообщение. Нельзя считать каждый ответ 200/302 доказательством успешного денежного действия: проверяйте последующее состояние или сообщение формы. Для автоматизации лучше использовать Flask test client и точные проверки результата.

Для запроса нужен тот же session cookie, с которым получен CSRF-токен. Токен передаётся в поле `csrf_token` либо заголовке `X-CSRF-Token`. Вход/регистрация очищают старую сессию: после них получите новый токен. Не публикуйте cookie jar.

```bash
curl -c /tmp/oilcoin-cookies.txt http://localhost:8080/api/csrf
```

Далее используйте выданный токен и `curl -b /tmp/oilcoin-cookies.txt -c /tmp/oilcoin-cookies.txt`, либо обычный браузер, который уже делает это автоматически. Не помещайте реальные пароли в общедоступные примеры команд и журналы.

## Коды и ограничения

- `400`: неверный CSRF-токен, формат адреса или некоторые входные данные.
- `401`: неверные данные входа.
- `302`: обычная навигация после формы; для защищённого endpoint без входа — перенаправление на `/login`.
- `403`: генерация demo или ручной quick mining выключены.
- `409`: арена отклонила игровое действие; причина в JSON message.
- `404`: отсутствующий блок/транзакция/маршрут.
- `405`: метод не разрешён, например GET вместо POST для выхода или POST в read-only debug.
- `413`: тело запроса превышает лимит приложения.
- `429`: слишком частые запросы.
- `503`: база недоступна или состояние не прошло проверку целостности.

POST-запросы ограничены фиксированным минутным окном по IP и endpoint: обычно 20, старые действия базы — 60, colony action/sync и arena action — по 180, лабораторный майнинг — 10, генерация demo — 1. Несколько игроков за одним NAT делят лимит соответствующего endpoint. За nginx включается `TRUST_PROXY=true`; прокси должен заменять пересылаемый IP, а прямой порт приложения оставаться закрытым. Это базовое ограничение для учебного стенда, не защита от распределённой нагрузки.

API не имеет стабильного версионированного публичного контракта или пагинации полной цепочки. Большая история увеличивает стоимость чтения, валидации и размера ответа. Не опрашивайте `/api/chain` несколько раз в секунду. Для внешних сервисов используйте HTTPS и учитывайте ограничения прокси/приложения.

`/debug` и `/debug/state` показывают публичное диагностическое состояние; они не предоставляют операции изменения цепочки. Сброса сети через HTTP нет.

## Остров, профиль и строительство

`GET /base` — текущий остров, `GET /api/base` — его JSON (ресурсы, уровни, legacy jobs, планировка, серверное время). Нужен вход. `GET /base/<address>` публично показывает здания и достижения без запасов и форм владельца. `GET /rankings?mode=pvp|week|base|xp` — рейтинг, по умолчанию pvp; неизвестный режим даёт 400.

`POST /api/colony/sync` с CSRF возвращает `{farm,world}`, фиксирует проекцию производства, активность и готовые улучшения. Блоки добывает отдельный worker. `world` содержит profile, network, flow, energy, jobs, shop, avatars, worker, buffer, builder_cost, expansion_cost и now. Интерфейс вызывает sync каждые десять секунд на открытой базе. `GET /profile` показывает выбор аватара.

Form POST `/colony/action/<action>` требует входа и CSRF, результат — redirect и flash. Отправитель определяется сессией; адрес в форме не подменяет игрока.

| action | Поля | Назначение |
|---|---|---|
| `collect` | Нет | Перенести все доступные буферы в свободное место склада |
| `allocation` | `fuel_pct`, `parts_pct`: целые 0–100, сумма ≤100 | Новые доли с момента действия |
| `buy` | `kind`: pipe, pump_station, workshop, fuel_station, compressor, battery, warehouse | Купить объект в инвентарь |
| `builder` | Нет | Купить следующего строителя, максимум 5 |
| `expand` | Нет | Купить 10×10 или 12×12, проверяется штаб |
| `avatar` | `avatar`: card:0…7 или adviser:0…3 | Сменить оформление |
| `tutorial` | `step`: 0–5 | Шаг обучения; 0 — начать заново |

`POST /base/action/build` принимает `kind` (hq/pump/depot/refinery/garage), ожидаемый `target` следующего уровня и CSRF. Детали списываются, подписанный OIL-платёж резервируется; стройка начинается после блока и завершается автоматически. Нужен свободный строитель и отсутствие активного улучшения этого же здания. Все активные стройки находятся в `world.jobs`; legacy `farm.build` показывает только первую.

## Планировка и рынок

`POST /base/action/layout`: `layout` — JSON-массив `{kind,x,y}`, `revision` из layout, CSRF. Размер берётся из профиля, не из формы. Координаты целые, footprint зданий 2×2, труб/декора 1×1. Пять основных зданий обязательны по одному; дополнительные станции/трубы ограничены купленным количеством. Декор road/tree/monument оплачивается по приросту количества. Сохранение сначала рассчитывает ресурсы по старой сети; устаревшая revision отклоняется.

| Метод и путь | Поля / результат |
|---|---|
| `GET /market` | HTML; resource=crude/fuel/parts и page, NPC-предложения |
| `POST /market/sell` | resource, quantity 1–1000, price за весь лот 0.01–10000 OIL |
| `POST /market/buy` | order_id; цена и комиссия только из БД |
| `POST /market/cancel` | order_id своего открытого лота |
| `POST /market/npc` | slot и offer из актуального предложения; направление, цена и резервы проверяет сервер |

Рыночные POST требуют CSRF, входа и штаба 2. Ответ — redirect/flash, не гарантия успеха по одному HTTP 302. Оплаченный ресурс доставляется после блока в общей транзакции сохранения цепи. Pending не отменяется и не истекает. Публичного произвольного endpoint выдачи ресурсов нет.

## Карты и сундуки

`GET /cards` — HTML коллекции. `POST /cards` с CSRF принимает action:

| action | Поля |
|---|---|
| chest | kind=scout/captain/admiral, request_id (8–64 символа), payment=oil/resources; для oil — quote из HTML, TTL 300 с; resources только scout |
| deck | шесть повторяющихся полей card с разными открытыми ID 0–7; порядок задаёт колоду |
| upgrade | card_id, сервер проверяет дубликаты, детали и уровень |
| build | card_id, branch=0/1, leaf=0/1 или пусто; уровень 2 для ветки, 3 для таланта |

Повтор request_id не оплачивает и не открывает второй сундук. Ответ — redirect и сообщение, после него HTML показывает результат последнего сундука. Уровни и колода активного матча не меняются от правки коллекции.

## Онлайн-PvP

`GET /arena` — HTML мини-игры. `GET /api/arena` — `{match,waiting,world,cards}` текущего игрока. Можно передать match_id; чужой матч не выдаётся. Когда матча нет, match=null; иначе содержит id, status, side, tick, units, players, winner, reason, rewards, started и server_now. Своя колода, эликсир и hand_revision доступны; у соперника они удалены. Чтение не рассчитывает бой и не выдаёт награды.

Все команды — form-encoded POST с `X-CSRF-Token` или csrf_token, session cookie и входом:

| Путь | Поля | Ответ |
|---|---|---|
| `/arena/queue` | mode=join/private/cancel; room — шестизначный код, если вход в комнату | `{ok,message,state}`; 200 или 409 |
| `/arena/play` | match_id, card_id, lane=0/1, revision собственной руки | `{ok,message,state}`; 200 или 409 |
| `/arena/surrender` | match_id | `{ok,message,state}`; 200 или 409 |
| `/arena/heartbeat` | Нет | `{ok:true}`; обновляет активность игрока и поиска |

Клиент читает состояние примерно раз в секунду и отправляет heartbeat раз в десять секунд. Очередь истекает через 45 секунд без heartbeat. Сервер проверяет энергию при фактическом подборе и тратит 3 с каждого участника. Редакция руки защищает от устаревшего/повторного розыгрыша, match_id — от попадания запроса в другой бой. Тело запроса ограничено 16 KiB. При потере сессии возможен redirect на login, поэтому JS проверяет Content-Type ответа.

## Совместимость старой кампании

Сохранились POST `/base/action/collect`, finish-build (job_id), claim-production (job_id), contract (contract и day), expedition (sector и approach), claim-expedition (job_id). Они проверяют владельца и однократность результата. Старое производство `produce` выключено в обычной конфигурации; флаг `ALLOW_LEGACY_PRODUCTION` используется только в тестовой конфигурации Python. Новые игроки используют `/colony/action/collect`, автоматические линии и PvP. Старые endpoints сохранены для прогресса предыдущих версий, не являются текущим сценарием основного интерфейса.

## PvE, билды и доставка сундуков (версия 5)

`GET /campaign` — экран кампании. `GET /api/campaign` — `{match,waiting:null,world,cards,stages,bosses,daily,completed}` только текущего игрока. У бота скрыты рука, эликсир, уровни и полный снимок характеристик. `players[].tower_max` содержит стартовое HP одной башни. `units[]` расширены боевыми характеристиками, `action`, `action_tick`, `healing`, `slow_until`; `events[]` — визуальные события последнего такта. В PvE есть `pve` (режим, параметры этапа, босс, ключ дня/этапа), `boss_event` (последняя способность).

| POST | Поля | Ответ |
|---|---|---|
| `/campaign/start` | mode=stage и stage=1..12; либо mode=daily | `{ok,message,state}`; 200/409 |
| `/campaign/play` | match_id, card_id, lane=0/1, revision | `{ok,message,state}`; 200/409 |
| `/campaign/surrender` | match_id | `{ok,message,state}`; 200/409 |
| `/campaign/heartbeat` | Нет | `{ok:true}` |

Обязательны вход и CSRF. Один активный PvE/PvP на игрока; перед PvE нужно отменить поиск PvP. Параметры победы, лут, время и силу бота клиент не задаёт. GET остаётся чтением, такты и награды записывает worker или команда боя.

`GET /api/cards/orders` возвращает последние десять собственных заказов `{orders:[{id,status}]}`; statuses pending/opened. Страница карт опрашивает этот endpoint каждые пять секунд при ожидающей оплате. Если игрок редактирует колоду, доставка не сбрасывает введённые значения: появляется уведомление; иначе страница обновляется автоматически.

В `world.storage` по каждому ресурсу: stored, used, reserved, capacity, take, remaining, percent. `take` — сколько поместится при текущем сборе, `remaining` — сколько останется готовым; процент учитывает исходящий и входящий резерв рынка, отображение ограничено 100%, реальные наградные излишки сохраняются.
